# 行動端測試設計指南

在提議新測試情境、評估測試覆蓋率、精簡冗餘案例或規劃行動端端到端使用者旅程時使用此技能。

## 1. 高價值情境設計

- **聚焦關鍵使用者旅程**：優先涵蓋對商業與使用者影響最大的核心流程（如結帳流程、登入驗證、核心瀏覽）。
- **風險導向優先級**：針對系統整合風險高、資料一致性要求嚴格或複雜狀態轉換的情境給予較高優先權。
- **明確的 Defect 偵測價值**：每個測試案例都必須有清楚的缺陷假設：*這個測試能抓到什麼具體且合理的缺陷？*

## 2. 隔離且可獨立執行的測試

- **零順序相依**：測試必須能獨立執行，或以任意順序執行而不影響結果。
- **各自建立前置狀態**：每個測試應自行準備必要的前置條件（透過 API、後端資料準備或明確導航），不依賴前一個測試的殘留狀態。
- **乾淨的 Teardown**：測試完成後應確保應用程式與環境恢復乾淨狀態，避免影響後續測試。

## 3. 行動端特有風險與生命週期考量

設計行動端測試情境時，必須考量 Android 平台的特有行為：
- **應用程式生命週期**：考慮背景運作、前景返回以及系統記憶體吃緊時的行程重建（Process Recreation）。
- **動態中斷處理**：系統權限提示對話框、系統通知與實體/虛擬導航按鍵互動。
- **螢幕與規格差異**：不同螢幕比例、解析度密度以及虛擬鍵盤彈起時對 UI 元件的遮蔽。
- **網路波動性**：真實行動網路延遲與非同步渲染，驗證必須等待畫面真正進入穩定狀態。
- **返回堆疊管理**：返回鍵點擊是否回到正確的父層畫面與狀態。

## 4. 範疇收斂與剔除冗餘測試

- **避免冗餘的 Happy-path 變異**：不要在昂貴的行動端 E2E 測試中重複覆蓋微小的外觀或文字差異。
- **測試下移原則**：欄位邊界檢查、格式驗證與 API 合約驗證應下移至單元測試或 API 測試執行。
- **具實質意義的 Assertion**：斷言使用者可感知的狀態變化（如確認訊息、購物車數量更新），而非僅確認沒有當機。
